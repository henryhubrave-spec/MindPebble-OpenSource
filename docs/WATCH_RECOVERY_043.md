# 手表 0.4.3：持续记录与故障恢复

2026-10-19。手机仍为 0.4.4，手表包名和签名沿用既有安装。

## 已发现的问题

录音器可能发生 IllegalStateException，导致服务退出且只留下临时片段。缺少原始异常堆栈时不能判定具体触发原因。

旧实现遇到录音器异常即停止服务，返回 `START_NOT_STICKY`，并把系统空启动意图解释成停止；这些行为使一次异常发展成持续断录。

## 恢复行为

- 将用户意图 `running / paused / off` 与当前录音状态分开，并同步保存递增代数。过时代数的闹钟不能覆盖新的暂停或停止。
- 录音器异常释放资源、保留中断文件，按 3 / 10 / 30 / 60 秒重试。成功开始后重置退避。明确记录恢复中的状态。
- 通话/通信/铃声音频模式、低电量（未充电且不高于 5%）、空间不足 64 MiB 时等待条件恢复。常规提示音不单凭声音触发暂停。
- 前台服务返回 `START_STICKY`；应用重启、开机和覆盖升级后只恢复仍开启的记录。闹钟和 15 分钟 JobScheduler 为进程退出提供补偿；健康运行时刷新心跳，文件持续两分钟不增长则重建录音器。
- 手动暂停或停止先同步撤销恢复意图，再保存/释放资源，同时取消重试、闹钟及守护任务。不会因为开机、升级或旧闹钟自行恢复。
- 保存失败保留临时文件，并在手动暂停/停止时显示未完成片段已保留。重启时只修复能够解码且有采集日志的片段，不能修复的文件保留。原 AAC 分段、标记、蓝牙同步和既有归档策略保持使用。

恢复需要系统调度，不承诺零缺口或固定恢复时限；系统“强行停止”会阻止后台任务，需再次打开应用。权限撤销后不能继续使用麦克风。尚未实测真实来电、其他应用抢麦、全天温升和续航。

## 诊断与验证

私有 `files/diagnostics/capture.jsonl` 记录命令、服务生命周期、录音器阶段/错误、重试时间、保存和同步结果；单文件约 96 KiB，保留一份轮转文件。不记录语音、文本、号码或配对凭据。

ADB 连接前确认 Codex 的 macOS 本地网络权限；设备显示 `unauthorized` 时需手表授权。排查先保存日志，之后再安装。原始诊断保存在被忽略的本地工作目录，不纳入 Git。

本次构建及测试结果见 [验证记录](VALIDATION.md)。故障注入只在禁用宿主音频的独立模拟器执行，不在用户设备上杀进程或制造录音器故障。


## 麦克风竞争

通话或其他语音助手占用输入时，应用可能无法及时恢复。系统强行停止会阻止后台恢复；需重新打开应用。不要根据单次恢复测试承诺固定延迟或全天无缺口，也不要自动停用系统应用。
