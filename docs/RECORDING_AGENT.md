# 录音理解工作流与转写整改

## 已接入的流程

手机本地 SQLite 编排，使用现有持久化 jobs 队列，API 只处理用户确认范围。

1. **原始资料与阅读视图**：speech_json 保留原始识别文字、片段与云端完整响应；完整原文按来源时间和说话人展示并支持一键复制。过滤纯标点、短且身份不明的常见语气碎片；否定词、有效短句和人工确认内容保留。全部碎片仍可从逐段校对展开核对。
2. **移动 ASR**：VAD 只判断哪些 30 秒上下文窗口需要识别，不把每个 2 秒 VAD 岛作为一次 ASR 请求；不足 10 秒的连续尾部拼回上一窗口。五分钟有人声录音最多约 10 次识别。窗口时间不是句级强制对齐时间；声纹也只是窗口候选，多人重叠不分离。不同声音特征明显不一致时保持身份不确定。
3. **事实先行**：支持该协议的 OpenAI 兼容服务可在 LLM 配置启用严格 JSON Schema；原生 Claude 保持本地校验模式。首次模型调用提取 activity/topic/fact/decision/commitment/idea/task/self_report，保存原句 quote、unit_id、source_id。程序核验引用存在、quote 为原文连续片段；提取内容仍是待核对候选，引用有效不等于语义一定正确。
4. **事件状态**：模型以有序原文单元输出 CONTINUE / NEW_EVENT / CLOSE_EVENT / SPLIT；程序检查来源、时间连续性、已有事件 ID、引用覆盖与顺序。跨文件事件带上既有原文和原子事实重新总结。事件、语句、事实分别存储；支持人工命名、结束、拆分和合并，修改边界后提示重新分析。
5. **记忆关联**：只检索已确认且仍有效的记忆；SQLite FTS4 为中文增加相邻双字检索词，不依赖向量服务。项目、人名、目标和待办词可以从同一检索入口找回。关联建议需要用户确认，未确认记忆不升级为既定事实。
6. **事件命名与总结**：第二次模型调用读取已校验事实及完整事件原文，生成每段标题、总结和整体回顾，保留原话和时间。两步均通过后事务保存，失败保留上次结果。
7. **日／周／长期回顾**：从 atomic_facts、tasks、已确认记忆与用户反馈读取证据，不仅读事件摘要。大范围按事实批次处理全部依据，不截取最近 30 条后冒充全天。每条结论引用存在的证据 ID，区分记录观察、本人反馈、AI 推测，并覆盖时间、社交、情绪线索、精力、目标、习惯六维；没有依据时留空。长范围结果按条目展示，事实批次之间不再用“摘要的摘要”替代证据。
8. **覆盖与基线**：录音覆盖按已同步区间求并集；窗口内语音时长只是范围估计。缺失录音不代表休息，没说话不代表没工作。最近 28 天不足 14 个记录日时明确基线不足，不能判断异常趋势。
9. **反馈与纠错**：本人精力 1–5、自评准确性和备注落库；原文、说话人、记忆修改保留纠错历史。改动使相关事件、回顾失效；发送与保存前复核来源版本和相关事件／记忆版本。重要事实、待办仍通过现有审核流程采用。
10. **队列与重分析**：全天原文一次确认后分组入持久化队列，每组执行时检索已完成的相关事件，因而可以跨组延续。失败、取消、进程中断可从任务页重新确认；远程请求不自动重复计费。删除手机来源同步移除相关事件、复盘和索引；导出包括新增结构化表。工作站上传与服务端保留策略由工作站控制。

入口：今日时光／语音回看 → **生活事件与分层复盘**。先分析当天原文，再生成指定日、截至所选日的周回顾、最近 30 天的长期状态。原文详情和连续回看也支持分析、命名与复制。

## 云端转写配置

按照项目根目录 `transcription.md` 实现两条路径：

- 标准接口：POST `/v1/audio/transcriptions`，multipart 的 file、model、language、prompt、response_format=verbose_json。保留 segments、words、语言、警告和原始响应；没有时间的服务响应明确标为未对齐。
- 个人工作站：POST `/v1/uploads/recording` 上传原始整段文件，再 POST `/v1/jobs`，传 capability 与 payload.recording/hotwords/模型参数；GET `/v1/jobs/{id}` 查询进度和结果。任务 ID 持久保存，重试可继续查询；取消时尝试 DELETE 同一任务，配置／密钥版本改变后不复用旧任务。

设置页支持标准／工作站模式、包含 `/v1` 的地址或完整 transcription 地址、Bearer 密钥、语言、1000 字以内热词、输出预算，及 `asr.default`、`asr.whisper`、`asr.moss`、`asr.meeting` 预设。Qwen 时间只是约 30 秒块边界；Whisper 保留逐词时间；会议编号仅在本次任务有效，不跨录音认人。`truncated=true` 不覆盖已有原文，响应留在任务里供核对。

同步标准接口保持通用服务 25MB 上限；工作站 asr.* 接口和异步上传上限 512MB。长录音建议工作站异步接口。

## 心率

最近有效值与最近采样结果分别保存。首页从最近多份同步资料寻找有效值，缺测不会覆盖已有心率；显示每项读数时间、较早值及本次缺测原因。没有数值时区分采样未开启、未授权、不支持和未收到有效事件；不会补造数值或据此诊断状态。未连接实体设备，不能据代码检查确认手表佩戴、权限和实际采样是否正常。

## 验证和评估

`tests/android/phone/AgentPipelineTests.java` 仅在 IntegrationTests 的 ranchu 模拟器保护之后运行。使用合成 WAV、固定文本和本地 mock HTTP，覆盖碎片规则、30 秒上下文、证据校验、跨来源／增量事件、FTS、迁移、纠错失效、两阶段服务、复盘落库、标准 multipart、异步上传／轮询、恢复和取消。

```sh
bash tests/android/build.sh phone
adb -s DISPOSABLE_EMULATOR shell am instrument -w -e phase agent-pipeline \
  org.diy.liferecorder.integration/org.diy.liferecorder.IntegrationTests
python3 -m unittest discover -s tests/agent -v
python3 tests/agent/evaluate.py --expected annotated.json --actual model-result.json
```

评估脚本输出事实召回、未匹配事实比例、事件边界精确率／召回率、待办精确率／召回率。应对同一批人工标注样本比较旧／新模型；精确引用匹配不能替代人工判断事实蕴含关系。真实工作站和真人多人场景的识别质量尚需联调，mock 测试不代表实际模型效果。

当前合成验证记录：Android 14 一次性模拟器 `agent-pipeline` 57 项通过，原文展示 1 项通过；云端配置和事件页面另做 UI 断言与截图检查。Python 评估工具 2 项测试通过。最终包为 `outputs/life-recorder-phone-0.5.0-debug.apk`；未覆盖安装实体设备，未使用私人录音或调用真实工作站。移动端长窗口模型的真实耗时、远场／多人识别效果仍需样本验证。

## 0.5.1 回看列表与长组分析修复（2026-10-20）

- 原回看列表只调用 `EventTimeline.group`，同一个 session 会一直拼接；语义事件虽已保存，却没有用于该列表。现在列表读取有效的 `life_events/event_units`，按事件名称、来源时间和总结显示，同一个音频内部可有多个事件，跨文件事件仍可合并。点击进入该事件，只展示对应的原文语句，并可从语句时间回听来源（兼容 VAD 保留映射）。
- 尚未分析或原文已纠正的内容标为“待整理录音”，每个时间组限制约 30 分钟。这只是待整理浏览范围，不是语义事件边界，不改动原音频。部分语句尚未覆盖的来源仍保留待整理入口。
- 连续回看 AI 按钮原来将整组传给最多 30 个来源的单任务，127 段会在创建时失败。现使用 `analysis_batch`，跳过无有效原文的来源，按时间排序、最多 8 个来源且以实际序列化快照 65,000 字符预算分批。队列创建保持事务性，异常不留下半批任务。同一时刻入队按 rowid 保持批次顺序；运行时重新读取已完成事件，继续跨批次关联。
- 完整原文区域现在从所有选中来源读取有效事件，不再只依赖第一条录音的分析缓存。增加“AI 按事件整理当前时段”，复用现有联网确认。历史录音需要执行该操作并在完成后刷新，才能生成语义事件；没有自动上传尚未授权的原文。
- 创建任务失败显示具体可处理原因（如先完成转写、选择更小范围），不再统一归因于 API 配置。超过单次预算的单个来源仍明确拒绝，且整次创建回滚。

验证：Android 14 新建一次性模拟器，`agent-pipeline` 209 项检查通过（含原有模拟 API 流程、127 来源完整分批、首段无文字、快照预算、原文纠正失效、事务回滚），`events-fix-ui` 4 项通过（同一文件显示两个语义事件、单事件精确原文、时间回听入口）。人工检查 `work/event-fix-emulator/event-cards.png`。使用合成音频和模拟 API，没有读取实体手表私人录音，也未调用用户的实际模型服务。

产物：`outputs/life-recorder-phone-0.5.1-debug.apk`（versionCode 11），签名校验通过；尚未覆盖安装实体手机。手表 0.4.5 包未改变。
