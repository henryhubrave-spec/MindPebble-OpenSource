# ADR 0001：三端边界与可配置处理

状态：历史v0.1设计提案。服务端/网关/密钥部署相关条目已由[ADR0002](0002-phone-local-agent.md)替代；以新决策为准。用户已明确的约束：开源、维护升级、Git迭代、重视两端美观、处理位置可配置。具体框架与界面仍可讨论。

| 决策 | 理由 | 代价/复核点 |
|---|---|---|
| 一个仓库，独立模块/版本 | 容易跨端审阅与追踪协议变化 | 构建边界要避免依赖互相污染 |
| 保留API26录音基线 | 已有实机证据，减少重写风险 | Java/Views先保留，渐进抽接口 |
| 手机以原生Android为主 | 先处理HyperOS后台与折叠屏的真实问题 | 跨平台客户端以后用同一协议重建 |
| 服务端模块化单体+worker | 清楚拆分职责而不先堆微服务 | 作业租约与幂等必须实现 |
| 配置Agent入口，而非在各端散布所有模型密钥 | 可切局域网/云与供应商 | 配对和部署向导需要易用 |
| 原始片段与用户事件解耦 | 5分钟切段不污染用户时间线 | 引用时间与事件编辑需要稳定映射 |
| 无GMS主路径为自有网络接收端 | 避免核心依赖特定厂商服务 | 必须验证网络互通、后台限制与额外耗电 |
| 来源与删除优先于“更像人”的记忆 | 能核对、纠正和遗忘 | 多来源记忆的重算会增加工程成本 |
| Agent先草稿，后执行 | 先验证资料整理价值 | 早期自动化程度有限，但可逐步加连接器 |

拒绝的早期方案：在WATCH 2上运行LLM；按每个5分钟文件生成一篇首页摘要；把心率转换成未经验证的压力/HRV；用ADB作为正式同步机制；在一小时耗电测量中更新采集代码。
