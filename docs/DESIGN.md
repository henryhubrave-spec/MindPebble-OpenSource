# 当前 UI 设计依据

当前使用暖色原生界面；实现范围、API 处理方式与验证见 [STITCH_IMPLEMENTATION](STITCH_IMPLEMENTATION.md)。下文保留此前设计方向作为历史参考。

# 界面方向与交互规范

设计目标：中文自然、录音状态一眼可辨、信息密度克制。避免把工程调试日志、模型参数和几十个五分钟文件作为首页主体。旧概念草图不随公开快照分发。

## 视觉语言

手机以温暖纸色、墨色正文、少量琥珀色重点构成；深色模式保持相同层级。卡片只用于事件、来源或有边界的决定；不用为每个数字加一张大卡。中文不是后补翻译：字体、行高、断行和按钮长度从中文开始设计。

手表用纯黑底以适应OLED，白色关键文字、琥珀色标记、红色录音指示；颜色之外配文字。手机与手表共享语义色与图标含义，不强求两者使用相同布局。

基础token：8dp间距体系，正文16sp，辅助信息14sp；手机最小触控目标48dp，手表44–48dp。所有字号与触控目标需在实际圆屏和系统字体缩放下验证，CSS草图并不等价于Android dp/sp。关键内容进入圆屏安全区域，避免截断“停止并保存”。

不做持续跳动的假波形。实际音量条只有真实麦克风电平可用时显示；待开始与暂停不用动画假装正在采集。

## 手表状态矩阵

| 状态 | 主信息 | 主操作 | 次操作 |
|---|---|---|---|
| 待开始 | 待开始、剩余空间/未同步数量（需要时） | 开始 | 同步/最近记录 |
| 生活记录中 | 原创可爱小伙伴+“生活记录中”、时长；麦克风状态明确 | 标记重点 | 暂停、停止保存 |
| 已暂停 | “已暂停”、当前段已保存 | 继续 | 停止保存 |
| 中断/错误 | 已中断、原因、已保存到哪里 | 查看并重新开始 | 保留/导出未完成片段 |
| 空间不足/低电 | 已停止与原因 | 查看状态 | 在条件恢复后手动开始 |

停止是明确动作，不只靠长按logo或隐藏手势。按钮焦点、读屏名称与状态描述必须完整。录音计时使用单调时钟，回顾日期使用用户时区；同步等待不让计时归零。

## 手机信息架构

“今天”先显示事件与重点；顶部设备状态是“最近收到xx分钟前”，不能把最后一次接收冒充当前仍在录音。覆盖条区分已录、未同步、真实中断与暂停；原音频不在时标记无法回放。

事件详情按“摘要 / 原文 / 回放”切换。结论和待办旁有来源入口，点击跳到对应原句与时间；AI解释以明确标签呈现，不与原话混排。检索无结果、模型不可用、处理中、权限被拒绝都有独立空状态。

“待办”先展示建议，不显示未经同意的“已替你发送”。“回忆”允许更正、暂不采用和遗忘。确认删除要说明影响哪些衍生结果与设备。

“AI API配置”分别填写转写与分析地址、模型和遮罩密钥；Agent编排与记录都留在手机。保存设置不联网，真正调用时展示接收主机与资料范围，不默认附健康数据。VAD在手机设置默认关闭，开启偏好与实际引擎/手表确认状态分开。

## MIX Fold 4适配

外屏：单列时间线→事件详情。展开屏：事件列表与详情并排，保留选择和播放位置；不把单列卡片拉到整个宽屏。旋转、折叠与字体放大时不丢输入或重启播放。尺寸按窗口断点判断，不硬编码某台设备的像素宽度。

## 首次使用

先说明采集、存放与处理去向→配对→做20秒测试→在手机播放确认→再配置转写/模型服务。没有配置AI也能完成这一圈。健康/位置权限在用户开启对应功能时再请求，不为录音先索要全部权限。

## 概念草图与真实实现

草图可切换手表录音状态、手机主入口、事件来源和ASR/LLM API配置；按钮仅改变示例界面。它用于讨论层级和流程，不代表已实现手机App、联网、真实健康分析或Agent。

## 新参考图的吸收

用户提供的六张Auday宣传图强调：关键词/语义查找后回原文、记忆审核/编辑/停用、身体线索到原话、上下文总览与可配置AI。仅用于信息架构参考，不复制商标、图形或文案布局。

手表主文案采用用户指定的“生活记录中”；用原创小脸而非持续波形或大段工程状态，暂停时呈安静表情。麦克风开启标识保留，VAD默认关闭；仅在引擎确实生效时等待状态显示“等待说话 · 暂不存静音”，不让亲切文案掩盖实际采集。

手机分别显示记录跨度与保留语音时长，覆盖条区分VAD省略、真实中断和语音留存。回放区同时展示原始时刻与精简音频位置；环境标签只说明实际信号，不直接贴压力或情绪标签。记忆持续保持候选、采用与停用的区别。

手机首切片已实现本地导入、播放与配置，视觉上采用同一暖纸色/墨色/圆角；四入口、展开双栏、AI和Agent完整交互仍是概念稿，不能将草图验收当作原生端实现验收。
