# MindPebble 手机 0.5.4 / 手表 0.4.5 安装与配对

日常数据同步只用蓝牙，不用 Wi-Fi、热点、IP 地址或 Google 服务。手机 Agent/VAD 保持本地运行；仅用户确认的模型请求使用网络。

## 1. 安装两端新版

手机自行安装 `life-recorder-phone-0.5.4-debug.apk`，按系统提示允许安装该来源。Mac 先在「系统设置 → 隐私与安全性 → 本地网络」允许 Codex，手表开启开发者模式、ADB 调试并授权该电脑，完整图文式步骤见 [手表部署教程](WATCH_DEPLOYMENT.md)。手表通过 Mac ADB 覆盖安装 `watch2-recorder-0.4.5-debug.apk`：

覆盖安装前先在设备暂停并确认当前片段成功保存；安装脚本必须在同一控制流程核对这两个状态，任何失败立即终止。不要使用未核对状态便直接执行的安装命令。本轮仅更新手机功能，已使用兼容手表版本时无需更换手表包。

ADB 此处只是安装工具，调试阶段用 Wi-Fi 与 App 日常蓝牙同步无关。已安装手表 0.4.2 时本次只需覆盖升级手机；从更早版本升级时两端均需更新。v0.2 的 App Wi-Fi 配对不能沿用，录音与手机设置/数据保留。包名和签名沿用旧版，不要卸载旧 App 来升级，卸载会删除私有数据。

## 2. 系统蓝牙配对

手机与手表都打开蓝牙，并在附近。已使用 Wear OS App 连接手表时，通常已有系统配对记录；是否可用以手表 App 的已配对列表为准。无需解除 Wear OS 连接或关闭手机正常网络。

新版采用 Android 安全 RFCOMM 双端直连，只显示已系统配对设备，不扫描陌生设备、不申请定位权限。若手表列表没有手机，请先在系统/Wear OS 完成配对。个别旧固件对 RFCOMM 的支持仍需实测，系统蓝牙显示已连接不能替代本 App 传输验收。

## 3. App 配对与同步

1. 手机 App → 高级设置 → 设备与采集 → 手表连接与文件接收 → 开启蓝牙接收。Android12+ 允许“附近设备”权限；蓝牙没开时会请求打开，通知权限用于显示接收状态。
2. 手机生成八位配对码，有效五分钟、一次使用、最多五次失败。
3. 手表 → 连接手机 / 同步（可向上滑动找到）→ 选择已配对的手机，核对设备名称/蓝牙地址 → 填码 → 通过蓝牙配对 App。
4. 手表点“立即蓝牙同步 / 更新设置”。手机打开“今日时光”，确认历史录音与新录音可播放。旧手表录音会保留；首次积压传输可能需要等待。
5. 手表 0.4.5 约十分钟一段，约三十分钟周期任务批量尝试蓝牙同步，也可手动同步；系统可能延迟后台任务。断开连接不删除原件，已确认文件重传去重。

手机 App 接收必须开启；前台通知代表服务已请求运行，不保证 HyperOS 永不结束进程。若被系统关闭，重新打开 App 接收并在手表重试。关闭蓝牙会终止当前传输，之后需重新开启接收。没有回执的片段稍后按完整文件重传，暂不支持单个文件内的断点续传。

## 4. 设置与数据

VAD 默认关闭，开启后在手机生成语音副本，默认保留完整原音。只有另外确认“仅保留语音”才释放手机完整音频；手表清理另行确认。心率、步数、气压、光照全部可选，设置通过蓝牙下发，下一段采集生效；心率还需手表授权。

ASR/LLM 地址、模型、Key 分别配置。只在确认后发送所选音频/文字，Key 不上传到项目服务器、不进导出。调用公网模型意味着确认的数据会离开本地；配置自有局域网模型可以保持在自有网络中。

导出 ZIP 不含 Key，支持新版完整备份在空资料库恢复。删除手机来源会删除关联记忆/待办/context，并防止手表重传恢复；手表原件独立保留。清理手表必须先重新核对手机副本。

## 5. 实机验收

先手动同步一段并试听，再超过十一分钟后台录音，确认自动分段/同步。暂时关闭蓝牙后继续录制，恢复并重新开启接收，确认补传与去重。最后逐项开启传感器、VAD，分别对照验证。不要根据模拟器或文件体积推算续航。

## 6. 离线任务与本人声音

设置 → 语音与智能处理，可管理语音包、自动处理和本人声音。本人声音支持直接录制。右上角“任务”查看接收及处理进度；历史等待任务可点击“立即处理等待中的离线任务”。LLM 仅通过 API 使用。见 [0.4.1 验证说明](TASK_CENTER_041.md)。

流程优化：自动整理授权撤回、固定分析范围、删除完整性、增量搜索，以及完整备份/空库恢复，见 [流程优化说明](PROCESS_OPTIMIZATION.md)。
