# MindPebble 0.4.2

## 这次调整

1. 手表的持续录音通知改为标题 **MindPebble**、正文 **正在记录您的生活**。英文随手机语言设置在下次同步后应用。
2. 任务中心支持“处理中与等待中 / 已完成 / 失败与已取消 / 全部记录”筛选。修正右上角任务数在窄屏换行被截断的问题。
3. 语音模型改为单线程运行，系统报告 SEVERE 时降低负载并在分段间让出 CPU；达到 CRITICAL 才暂停，降温后恢复。手动处理不再被 SEVERE 状态永久挡住。仍保留内存不足和临界温度保护。资源缺失显示等待下载与验证，不把整批队列标为失败。
4. 波形由实际解码 PCM 的 RMS 包络生成，批量读取并缓存，避免逐字节读取导致长时间只显示占位点。加载和失败有明确提示，播放精简版时切换对应波形。
5. 连续记录直接进入连续回看：同一时间轴、全局拖动、跨片段自动续播和合并原文。取消原有 90 分钟分组上限；原始文件仍分段保存，便于中断恢复。真实录制间隔不伪装成无缝采集。原始片段收纳在详情管理中。
6. 待办菜单支持删除并取消对应提醒。语音支持删除手机音频但保留文字、删除手机整条记录、仅删除手表原件、或两端删除。删除整条记录会清理关联待办。
7. 设置 → 数据与隐私 → 原始音频管理，分别查看手机副本、最近同步的手表清单和删除指令状态。手表指令绑定文件名和 SHA-256，持久化保存，收到手表确认才显示完成。断连时显示等待，不假装删除成功。
8. 手表仅对**手机已收到、已整理、录制时间超过 7 天**的完整片段自动清理；如有环境文件，也需已确认传到手机。未同步、未整理或临时录音保留。周期同步与后续同步会执行清理，系统可能延迟周期任务，不能保证精确到第 7 天某秒。手机保留时间由用户手动管理。
9. 蓝牙接收服务持久记住用户开启状态，支持系统重建及开机/蓝牙恢复；传输、离线处理期间保持 CPU 唤醒，空闲接收不持续持有 CPU 锁。收到音频后可启动本地自动处理，遵循自动处理及充电偏好。无互联网不会阻止蓝牙接收和本地转写。强行停止 App、系统拒绝后台运行或关闭蓝牙仍会阻止接收，设置中提供系统后台管理入口。
10. 设置 → 数据与隐私 → 语言 / Language：支持中文、English。界面、排队离线任务、识别语言和新 API 请求的回复语言使用该设置。英文离线转写使用标准 SenseVoiceSmall 包，未准备资源时明确等待；轻量 Zipformer 为中文模型。原始文字与人工输入保留，不靠 UI 词典翻译用户数据。LLM 始终只通过 API。

## 同步兼容

新协议 SYNC2 使用有长度限制的 UTF-8 清单，支持库存、删除指令、回执与保留策略。新手表先用旧协议探测能力，再切换，因此手机尚未升级时仍可同步音频。完整音频管理要求双端均升级至 0.4.2。旧包名、签名及本地数据保留，数据库 v7 → v8 增加资产删除标志及手表清单/指令表。

## 验证

仅在专用 Android 14 ARM64 ranchu 模拟器操作测试数据，录音测试使用 `-no-audio` 禁用主机音频。

- 使用公开中文音频重复构造 561.15 秒录音；模拟 SEVERE 温度、未充电、飞行模式与熄屏，47 个分段经真实本地模型完成并存储文字，13 项断言通过。CRITICAL 状态正确阻止继续处理，结束后恢复模拟器温度/电池/网络状态。
- 标准 SenseVoice 使用模型作者公开英文样本，以 `language=en` 实际产出英文文字；界面选择与 API 语言快照通过。
- 实际音量强弱包络、全局定位和跨原始文件自动续播通过。
- 两端真实协议实现经内存管道端到端联测，验证新音频到达手机、手机下发手表删除、删除回执落盘、过期已整理音频清理及未整理原件保留。此测试不能代替实体蓝牙射频、HyperOS 后台保活及实体手机温控验证。
- 手表独立验证哈希不符不删除、重复指令幂等、未接收/未整理不自动清理；旧同步、录音恢复测试通过。
- 删除手机音频后保留文字/待办、阻止重新导入、保留远端删除指令及删除待办通过；旧数据库与蓝牙协议回归通过。

测试阶段和复现方式见 `tests/android/README.md`。历史合成回归不能替代设备兼容性验证。
