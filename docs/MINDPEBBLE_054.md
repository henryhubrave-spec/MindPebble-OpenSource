# MindPebble 0.5.4 · 自动逐小时总结

新增自动逐小时总结，沿用手机 App 的 Serene Hearth 暖白、陶土色与鼠尾草绿界面。首页与语音回看均提供入口，按日期查看该天有录音的小时，可点击引用进入对应原文和原声位置。

## 使用

1. 打开首页「逐小时总结」，或语音回看中的「查看当天逐小时总结」。
2. 点「设置 → 配置分析 API」，填入自己的模型服务。
3. 点「设置 → 开启自动逐小时总结」，确认接收方与处理范围。

开启是独立的服务绑定授权，默认关闭，不沿用旧的语义事件整理开关。只发送该小时的逐句文字、说话人标签与来源时间，不上传原音或长期记忆。通常每小时一次请求；长原文分批处理，可能产生费用。更换服务或模型后，需要重新开启。

## 自动行为与内容规则

- 按手机当前时区的实际小时边界归档；支持跨午夜、夏令时缺失或重复的小时，以及半小时转换。
- 当前小时结束后再整理。历史已转写录音会补齐；同一份原文不会重复请求。转写晚到或人工校对时，立即使受影响小时的旧总结失效，再按新原文更新。
- 每个总结要点必须有可核对的原句引用。服务输出的来源编号和引用文字需通过本机验证；时间与录音编号由本机原文派生。AI 的归纳仍需用户核对，逐字引用校验不等于语义正确性保证。
- 跨整点的一句话归入其开始的小时，保留完整原句与原始偏移，不按字数伪造切分时间。只有未对齐人工文字的时段不会生成时间总结；已完成但未识别出文字的录音不会一直显示为待转写。
- 缺失录音不补写生活。部分转写已完成时可先整理，剩余待转写数量仍显示。覆盖时长按区间并集合计，重叠录音不重复计数。
- 删除来源会清除相关小时总结、证据快照与任务中的来源资料。只释放音频时仍可查看有文字依据的总结；界面明确原音不可用。
- 单小时长原文按约 24,000 字符分批，不静默丢弃后续语句。异常超长的单个句段会显示失败，提示先校对分段。

## 后台与恢复

使用独立的 Android JobScheduler / JobService，持久化周期检查为 15 分钟；开启、打开页面及转写更新时另提交至少 30 秒后执行的任务，合并密集更新。要求联网、电量和存储不低。系统省电、网络、应用被强制停止等会延后执行，不承诺整点立即生成；重新打开 App 会恢复检查。

任务与小时快照均保存在本机数据库。小时结果、完成状态与版本校验在同一事务中提交。原文修改会取消正在使用旧快照的任务；关闭或服务变更会阻止后续请求及旧结果提交。失败、取消或进程中断不会在原文不变时自动重试，避免重复计费，可在该小时点击重试。系统中断可能发生在服务已接收请求之后，因此显示「待确认重试」。

旧语义整理、问答与转写任务继续使用各自的执行器；逐小时任务不会被通用 AI 队列重复消费。更改手机时区会按新时区重新归档，旧时区的排队请求会取消。

## 导出与版本

选择性导出的「内容总结」现在包含录音总结与逐小时总结。`hourly-summaries/` 中输出 Markdown 和 JSON，保留来源、时间及引用；沿用日期/单条录音选择边界，引用所选范围外来源的小时会跳过并报告。只导出总结也附来源索引，不包含 API 配置、密钥或内部路径。

数据库由 11 增量迁移至 12，保留已有录音及校对；新增小时表、待处理区间表和来源修改触发器。手机版本 0.5.4（versionCode 14），输出 `outputs/life-recorder-phone-0.5.4-debug.apk`，手表版本保持 0.4.5。

本次只在专用 Android 14 模拟器使用合成录音、隔离数据库与本机模拟 API 验证，没有连接实体设备、读取私人录音或调用用户的真实模型服务。测试结果见 [验证记录](VALIDATION.md)，截图在 `outputs/mindpebble-0.5.4/`。
