下文为 v0.3 基础架构；蓝牙协议与凭据沿用。

# v0.3 双端蓝牙本地架构

```text
手表 MediaRecorder / 可选 SensorManager
  → 完成段 AAC + 时间戳/标记 JSON + 环境 JSONL
  → 安全 RFCOMM 蓝牙，配对令牌，SHA-256 / 耐久回执
手机 SyncService → 私有文件 + SQLite RecordStore
  → 本地 VAD / 播放 / 搜索 / 记忆审核 / 待办与提醒
  → AgentService 持久任务队列
  → 用户确认后 ProviderClient → 用户配置 ASR / LLM
```

## 采集与传输

手表约每五分钟停止并重新准备 MediaRecorder，不保证无缝；暂停与停止保存当前段。临时 `.part` 不发送，音频与元数据完成后同步。每段独立 context，时间包括墙钟与单调时钟；段内重点偏移可以用于 VAD 保护与回放。

v0.3 数据流以 `0x4c523032` 标识，操作为 PAIR/SYNC。手机用安全 `listenUsingRfcommWithServiceRecord`，手表用对应 UUID 的安全 RFCOMM Socket。只接受系统已配对设备，不使用不安全 Socket、不扫描、不请求定位。手机 Android12+ 请求 BLUETOOTH_CONNECT，接收前台服务类型 connectedDevice；手表 API26 请求传统 BLUETOOTH，不需要 INTERNET 或 Wi-Fi 网络权限。

App 配对码八位五分钟、单次使用、最多五次失败。手机同时绑定实际 socket 对端的蓝牙地址与稳定手表 UUID，随机令牌 Keystore AES-GCM 加密保存；后续连接需同时匹配地址、UUID 和令牌。重新 App 配对使旧令牌失效，并清除旧接收方回执。v0.2 Wi-Fi 配对不自动迁移，必须手动重新确认。没有 TCP 监听、IP 输入或 TLS 证书入口；链路加密依赖系统安全蓝牙配对，不宣称额外端到端应用层加密。

BluetoothSocket 没有 SO_TIMEOUT，因此使用单调时钟45秒无数据进展看门狗关闭挂起通道；断线保留原件，以完整文件重传。两端使用有界缓冲，文件仍为每段独立校验与回执。

手机校验长度、SHA-256、媒体时长与基本元数据。文件写入和目录同步后才提交数据库并回执。重复 ID 同哈希去重，内容冲突拒绝；丢失副本可重新接收修复。`DURABLE` 表示完整副本已保存，`SPEECH_ONLY` 表示用户明确只保留语音的派生状态，`GONE` 是来源已遗忘。后两者有不同语义，不能混同完整原音备份。

同步不自动删除手表原件。手表清理必须用户操作并刷新回执，手机已遗忘项不会触发清理。自动同步为完成段触发及周期 JobScheduler，蓝牙/后台受系统调度限制；手动同步可见错误。

## 本地 Agent

手机以 SQLite 保存 ASR/分析/问答/回顾/VAD 任务。任务先记录再执行；不确定中断任务要求重新确认，不自动重试付费请求。模型地址、模型名和配置版本被快照，Key 执行时从 Keystore 解密；配置变更会使旧任务失效。ASR 冻结音频路径与哈希，分析冻结原文，问答/回顾冻结选择的来源与已采纳记忆，防止确认后静默扩大范围。

分析输出为摘要及候选记忆/待办，均关联来源，用户审核后生效。转写文字视为不可信资料，没有任意代码、工具或外部行动执行能力。模型输出仍可能错误，来源与原文可核对。当前只实现文字匹配搜索，不提供向量索引。

## 数据与迁移

RecordStore 数据库版本 4，升级按版本添加环境来源、派生保留状态、导入/原始时间等字段。v0.1 音频复制迁移，旧私有音频暂不自动删除。旧协议 schema 是契约参考，运行时协议不声称已完全使用其全部字段。

删除来源级联删除记忆、待办、任务及 context，保留 tombstone 防同步复活。ZIP 导出无 Key，支持 v3 完整备份在空资料库恢复。音频和数据库依赖 Android 应用私有目录与系统存储保护，没有额外应用级全库加密；Key 与配对令牌使用 Keystore AES-GCM 封装。关闭系统云备份/设备迁移规则；不把它描述成防越狱/防已解锁设备访问的保险箱。

本机只有接收服务和按确认发出的模型请求，无服务端 Agent、默认云存储或遥测。未来接入接口可替换 ProviderClient，不使 UI/录音依赖单一模型厂商。

流程优化：自动整理授权撤回、固定分析范围、删除完整性、增量搜索，以及完整备份/空库恢复，见 [流程优化说明](PROCESS_OPTIMIZATION.md)。
