# MindPebble 手机 0.4.3

手机 APK：`outputs/life-recorder-phone-0.4.3-debug.apk`（versionCode 8）。沿用原签名和数据库 v8，可覆盖安装；手表继续使用 0.4.2，本次不改变录制和同步协议。

## 使用

- 原始音频管理新增“待清理”：列出本地明确未检出人声、或 API 整理后建议清理的片段。连续回看与单段详情也提供提示。先试听，再选择仅删除手机音频、整条记录、手表原件或两端。每次仍需明确确认；手表删除在下一次同步后显示回执。
- 本地检测未发现人声，且没有人工/识别文字时，才提出本地建议。空转写、短对话、背景音和模型运行失败本身不构成删除理由。VAD 可能漏掉轻声/远场，因此保留试听和用户决定。
- LLM 仅通过配置的 API 接收原文、本地检测统计和用户选择的环境观察；不新增原始音频上传。模型可返回 `audio_review`（分类、布尔删除建议、理由）。仅接受约定分类与严格布尔值，并绑定当前原文 SHA-256；修改原文后旧建议失效。旧的分析需再次确认 API 分析才会生成新建议。
- 已登记的单模板声纹继续兼容。新登记提取多个有效语音窗口，过滤静音和明显低质量样本；用归一化模板、时长加权分组中心及组内一致性匹配。证据不足的段标为“身份不确定”，已人工确认的标签保留。
- 手机直接登记、手表采集会遇到麦克风差异。打开手表录音的单段详情，回听后点击“用本句补充本人声纹”，确认是本人单独清晰说话后添加（有效语音至少约 2.4 秒）。现有登记保留，保留初始登记模板，补充模板在 12 个总上限内轮换，不自动从预测结果训练。
- 补充后点击“重新匹配声纹（保留文字）”。只需声纹模型，不需要重新跑 ASR；结果保留文字、时间、摘要与人工确认标签。原音路径、SHA、原文版本变化会阻止覆盖。当前声纹仍为候选，不是已验证的跨天身份库，也不分离重叠人声。

## 验证

仅在 Android 14 ARM64 专用模拟器，使用公开/合成样本；未读取用户私人录音，未安装实体手机，未修改手表。

- `review043`：26 项断言，含删除建议前提、旧结论失效、严格布尔解析、旧模板兼容、同人变化/异人/不确定分组及人工标签保留。
- `speaker043`：9 项断言，实际运行 CAM++、Zipformer、SenseVoice，包括多窗口登记、同源音量下降和轻微噪声、不同公开说话人对比、真实前台仅声纹任务、保留原文与摘要、补充加密声纹、真实静音检测。
- `reviewapi043`：6 项断言，本地 HTTP 模拟模型响应经过实际 API 客户端和 AgentService，验证统计入参、建议保存、不会删除音频、修改原文后失效。没有调用收费外部 LLM，也没有验证特定供应商的噪声判定质量。
- 既有回归：`storage042` 10 项（删除回执、防回流、待办保留/删除）、`session042` 4 项（真实波形、连续播放和跳转、长时间分组）。长录音测试固定从本地中午开始，避免当前时间跨午夜误测按日分组行为。
- `tests/android/verify-043-ui.py`：中英文待清理、删除选项、仅声纹确认、补充声纹确认。测试仅打开后取消弹窗。

同源轻微噪声样本匹配分约 0.929，不同公开说话人约 -0.029。这些是有限样本回归值，不代表手机与手表真实场景的准确率；仍需用户在实机上试听确认、补充手表样本验证。

阈值参考 [sherpa-onnx speaker identification](https://github.com/k2-fsa/sherpa-onnx/blob/master/python-api-examples/speaker-identification-with-vad.py) 的 0.6 示例，并结合样本质量、分组一致性和不确定状态使用；多模板登记参考 [Java speaker identification](https://github.com/k2-fsa/sherpa-onnx/blob/master/java-api-examples/SpeakerIdentification.java)。没有把示例阈值视为跨设备准确率保证。
