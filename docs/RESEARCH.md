## 商业产品及开源项目交叉参考

### Auday：记忆回顾与自带模型服务

[官方FAQ](https://auday.ai/faq)描述：手表采集、手机本地转写与检索，配置的AI端点负责进一步分析；标记、摘要和回忆可以追溯原文。可借鉴“日常记录→可查阅记忆”的组织方式。官方也区分心率、HRV与估计的身体状态，未将其等同于情绪诊断。

我们的选择：原音频可配置保留；模型输出引用原始片段；WATCH 2没有验证的健康信号不补造。

### Plaud：主动标记与场景模板

[官方标记说明](https://support.plaud.ai/hc/en-us/articles/50609128298521-Highlights-Multimodal-Input)展示了录音时添加时间标记、文字和照片；[模板说明](https://support.plaud.ai/hc/en-us/articles/50636128812441-Summary-templates-choose-customize-and-set-a-default)说明了按场景组织摘要的方式。重要的是用户标记能够影响之后的整理，而不只是增加一篇通用总结。

我们的选择：手表“一键标记”；手机可补充上下文；模板是可版本管理的文件，先做会谈、灵感、每日回顾三种。

### Omi：从对话到记忆、待办、工具

[官方App说明](https://help.omi.me/en/articles/13153540-using-the-omi-app)区分会话、任务、记忆；[扩展说明](https://help.omi.me/en/articles/13153599-omi-apps)区分分析、聊天和外部工具集成。可借鉴扩展边界，早期无需复制整个平台或应用市场。

我们的选择：先生成可审核的待办草稿；外部执行独立授权。录音转出的文字始终是资料，不能自行授予Agent权限。

### Limitless：服务变化与数据可迁移

[官网公告](https://www.limitless.ai/)表示已被Meta收购、不再向新用户销售Pendant，并提供数据导出。它适合作为历史产品参考，不能当作仍正常面向新用户销售的现行推荐。

我们的选择：用户持有数据、可导出、可更换处理服务；停止某个模型供应商不会阻止已有录音播放和浏览。

### Speakr：可选处理适配器

[项目仓库](https://github.com/murtaza-nasir/speakr)提供自托管录音整理与可配置转写，并声明AGPLv3/商业双授权。适合作为独立可选集成，不预设为整个系统必装底座。不把其代码复制进MIT仓库；具体API/版本/许可适配在接入时单独评审。

## 功能优先级

| 优先级 | 功能 | 用户获得的价值 | 前置条件 |
|---|---|---|---|
| P0 | 可靠采集、可恢复同步、覆盖率/缺口 | 知道哪些内容真的被留下 | 实机续航和断连测试 |
| P0 | 播放、可检索原文、来源跳转 | 找回某句话并核对 | 转写及时间轴映射 |
| P0 | 按事件整理的时间线 | 不必管理几百个五分钟文件 | 文件与事件解耦 |
| P1 | 会谈摘要、灵感卡、每日回顾 | 减少重听成本 | 来源可追溯、可纠正 |
| P1 | 一键标记、待办草稿、跨天问答 | 留住重点、跟进承诺 | 证据片段和确认流程 |
| P1 | 记忆编辑、遗忘、整库导出 | 用户能掌控长期记忆 | 删除与重建机制 |
| P2 | 提醒、日历/笔记集成 | 从记录走向行动 | 独立授权和执行审计 |
| P2 | 步数/心率的可选上下文 | 观察活动与会谈的时间关系 | 单独功耗验证和用户授权 |
| 暂缓 | 压力评分、HRV、情绪判断、全天定位 | 收益尚未验证 | 不能从只有心率的数据推造这些指标 |

## 产品判断

“生活外挂”的核心是让原本会忘记的事实、承诺和想法变得可找、可核对、可跟进。早期不以摘要字数、模板数量或全天采集时长为成功指标。

先验证四个问题：一周里用户是否找回过真正想找的信息；待办草稿是否减少遗漏；处理失败能否看懂并恢复；用户是否能够随时停止、导出和遗忘。
