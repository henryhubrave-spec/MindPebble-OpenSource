# MindPebble 0.4.1

手机、手表显示名称均为 MindPebble。保留原包名和签名，可覆盖安装并保留数据。手机安装包为 `outputs/life-recorder-phone-0.4.1-debug.apk`，手表为 `outputs/watch2-recorder-0.4.1-debug.apk`。

## 本轮功能

- 本人声音：设置 → 语音与智能处理 → 本人声音，支持直接录制 5–30 秒、试听、重录和确认登记。需要先安装声纹包。样本仅暂存本机缓存，退出即清理，不进入录音库；声纹通过 Android Keystore 加密保存。
- 任务中心：各页面右上角“任务”入口，显示等待、处理中、已完成、失败的任务；提供查看来源、重试、取消和立即处理离线任务。
- 设置：设备与采集、语音与智能处理、数据与隐私三个一级分组，进入后展示二级设置。
- 接收进度：显示当前文件实际接收字节、文件百分比及本次已完成文件数。协议未预告总文件数，因此不编造整个同步会话的百分比。
- 离线处理：显示资源校验、解码、语音检测、模型加载及实际分段进度；未知总量的阶段显示不定进度。进度持久化到任务记录。
- 弹窗：统一暖色扁平面板、轻边框和扁平按钮，包含确认、日期和时间选择主题。

LLM 仍只通过用户配置的 API 连接。本地资源用于语音识别、语音检测和声纹，没有引入本地 LLM。

## 等待处理问题

原调度路径可能反复替换等待中的 JobScheduler 任务，推迟其开始时间；同时，“等待”未展示充电和资源限制的具体原因。现在复用约束相同的已有调度，保留后台自动处理，并新增用户主动触发的前台服务，不依赖后台调度配额。

安装新版后，进入右上角“任务”并点击“立即处理等待中的离线任务”，可处理历史队列。此操作仅将选定的等待任务改为手动处理，不改变“自动处理仅充电时”的设置。暂停、取消、内存不足和温度过高均有明确状态。

本轮没有连接实体手机，不能认定上述调度问题就是该手机等待的唯一原因。已在专用模拟器验证正常调度和立即处理均能产出真实转写；实体手机仍需安装新版验证。

## 验证记录

环境：Android 14 ARM64 专用 ranchu 模拟器，启动参数 `-no-audio`，使用公开语音样本及固定校验资源，没有读取私人录音。

- 未充电：自动任务正确等待；用户立即处理后走前台服务并完成，保留自动充电偏好。
- 充电：正常调度完成真实转写；未使用 `cmd jobscheduler run -f` 强制调度。
- 正常后台调度：44.892 秒音频完成 4 个分段，存储原文、时间范围及终态进度。
- 长音频：561.150 秒音频完成 47 个分段，处理约 14.9 秒，原音哈希不变。这是模拟器结果，不代表手机性能。
- 直接录制：实际 MediaRecorder 录制超过 5 秒、音频可解码、未进入录音库、退出立即删除样本。
- 声纹：真实模型提取、Keystore 加密、同一公开声音候选匹配及删除通过。
- 接收：协议内存流验证中间字节进度、两文件完成数与源文件哈希；不能替代实体蓝牙链路测试。
- 数据库 v6 → v7：保留旧队列及输入快照，不编造已有任务进度。
- 设置分组、录制入口、任务入口和扁平弹窗已运行 UI 脚本并检查截图。
